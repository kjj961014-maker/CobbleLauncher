# Cobble Launcher 설치·사용

## 현재 제공 버전

`release/CobbleLauncher-Setup-0.1.1.exe`는 Windows 64비트용 개발 빌드입니다. 이 버전은 화면과 설치 엔진을 확인할 수 있지만 운영자의 Microsoft 앱 승인·CurseForge 연결·실제 모드팩 구동 검증이 아직 필요합니다. 운영자 준비가 끝나기 전 일반 이용자에게 정식 완성품으로 배포하지 않습니다.

로그인 버튼을 눌렀는데 브라우저 창이 없으면 **계정 → 로그인 주소 복사**를 누른 뒤 Chrome 또는 Edge 주소창에 붙여넣습니다. 런처를 열어둔 채 5분 안에 로그인을 완료합니다. 중단하려면 **로그인 취소**를 누르고, 다시 로그인할 때는 새 주소를 복사합니다. 로그인 주소는 유효 시간이 있는 현재 요청이므로 게시하거나 다른 이용자에게 공유하지 않습니다.

## 첫 실행

1. 설치형 EXE를 실행합니다. 설치 폴더를 선택할 수 있습니다. 개발 빌드는 코드 서명 인증서가 없어 Windows에서 게시자 확인 안내가 나올 수 있습니다.
2. 시작 메뉴나 바탕화면의 Cobble Launcher를 실행합니다. 첫 화면에서 Microsoft 로그인 안내가 나옵니다. 화면을 먼저 둘러볼 수도 있습니다.
3. 현재 개발 빌드는 운영자의 Client ID가 비어 있습니다. `설정 → 계정 및 연결`에 승인된 Client ID를 입력합니다. 일반 이용자 배포본은 운영자가 이를 미리 설정합니다. 준비 방법은 `service-setup.md`를 확인하세요.
4. Microsoft 로그인 버튼을 누르면 기본 웹 브라우저에서 Microsoft 공식 페이지가 열립니다. Minecraft Java Edition을 플레이할 수 있는 본인의 계정을 사용합니다. 런처에 Microsoft 비밀번호를 입력하지 않습니다.
5. 인증이 성공하면 실제 플레이어 이름과 스킨이 표시됩니다. 계정 페이지에서 로그아웃하고 다른 계정으로 전환할 수 있습니다. 게임이 실행 중일 때는 계정을 바꿀 수 없습니다.

## 게임 설치

1. `설정 → 게임 환경`에서 **이 모드팩만 사용할 전용 폴더**와 RAM 할당량을 선택하고 저장합니다. 팩 제작자는 최소 8 GB 할당을 권장합니다. 운영체제와 다른 프로그램에 필요한 여유 메모리도 남기세요.
2. 모드팩 ZIP 경로는 현재 개발 PC의 제공 ZIP을 자동으로 찾습니다. 다른 PC에서는 공식 ZIP을 선택할 수 있으며, 경로를 비워 두면 승인된 API 연결로 등록된 ZIP 다운로드를 시도합니다. SHA-256과 manifest가 등록된 6.2.0 파일과 일치해야 합니다.
3. 개발자의 승인된 CurseForge 연결이 필요합니다. 현재 로컬 개발 검증용 키는 `설정 → 계정 및 연결`에서 입력합니다. 이 키는 Windows 보호 저장소로 암호화되며 화면에 다시 노출하지 않습니다. 키를 친구들에게 배포하는 방식은 사용하지 마세요. 운영용 연결 조건은 `service-setup.md`를 따릅니다.
4. 홈에서 설치를 시작합니다. 공식 Minecraft 본체, 게임 리소스, Java 21, NeoForge, 모드 330개·리소스팩 13개·셰이더 2개를 각각 준비합니다. 총 파일 345개 중 저작자가 다운로드를 허용하지 않은 파일이 있으면 해당 ID와 이유를 표시합니다.
5. 정상 파일은 캐시에서 재사용하고, 중단된 파일은 가능한 경우 이어받습니다. 용량·해시가 확인된 파일만 적용합니다. 완료 후 게임 실행 버튼을 사용할 수 있습니다.

## 실행과 업데이트

게임 실행 전에 계정 사용 권한과 관리 모드의 무결성을 검사하고, 연결된 서명 업데이트 채널을 확인합니다. 서버 주소가 설정되어 있으면 해당 서버에 접속하도록 실행 인자를 전달합니다. 서버가 설정되어 있지 않으면 임의의 서버 온라인 상태를 표시하지 않습니다.

운영 채널을 연결하면 90초마다 공지와 서버 상태를 확인합니다. 게임이 실행 중이어도 새 공지는 표시할 수 있습니다. 게임 파일 패치는 게임 종료 후 적용합니다. 바뀐 파일만 다운로드하고, 원본 백업과 적용 기록으로 실패 또는 중단된 패치를 복구합니다.

`saves`, `screenshots`, `options.txt` 등 개인 데이터는 업데이트 경로에서 제외합니다. 이미 사용자가 수정한 설정은 자동으로 덮어쓰지 않습니다. 보호 때문에 보류된 파일은 메시지로 표시합니다. 관리 대상 외의 파일은 자동 삭제하지 않습니다.

`게임 실행 후 런처 숨기기`를 켜면 창을 숨기고 게임 종료를 감시합니다. 게임이 끝나면 창을 다시 표시하고 대기한 패치를 확인합니다.

## 오류 해결

- Client ID가 비어 있거나 Minecraft 접근이 거부되면 운영자의 앱 등록과 승인 상태를 확인합니다.
- Java 소유권 또는 프로필이 없다는 오류는 로그인한 계정과 Minecraft Java 사용 권한을 확인합니다.
- CurseForge 401/403 또는 자동 다운로드가 막힌 파일은 API 승인·자신의 키·저작자 배포 정책을 확인합니다. 비공식 미러나 URL 추측으로 해결하지 않습니다.
- 설치를 취소한 뒤 같은 경로에서 다시 시도하면 정상 캐시를 재사용합니다.
- 실행되지 않으면 게임을 종료하고 `설정 → 파일 및 진단 → 게임 파일 검사 및 복구`를 선택합니다. 현재 패치가 적용된 경우 해당 서명 채널의 같은 파일로 복구합니다.
- 오류가 반복되면 로그 폴더를 열어 `launcher.log`와 게임 `logs/latest.log`를 확인합니다. 로그를 전달할 때 계정·개인 경로 정보는 확인하세요.

런처 기본 데이터는 Windows의 `%APPDATA%\Cobble Launcher`에 있으며, 게임 경로는 설정에서 확인할 수 있습니다. 제거 프로그램은 게임/설정 데이터를 자동으로 삭제하지 않습니다. 실제 새 PC 첫 설치 검증은 별도의 완료 조건입니다.
